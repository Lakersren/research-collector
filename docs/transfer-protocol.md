# 按目标发表日采集与同步

A 每天北京时间 01:00 采集昨天发布的文章。B 每天北京时间 06:00 同步昨天的归档。手动同步可在 B 执行 `sync.py 20261109`，也接受 `2026-11-09`。

## A 的文件

```text
data/archive/20261109/
  report.json
  report.md
  <来源>/
    <文章 ID 的 SHA-256>.txt
    images/<图片内容的 SHA-256>.<扩展名>
```

每个目标发表日保留一个目录，按北京时间保留最近七个目标日。JSON 记录各来源的采集状态、文章明细、正文和图片的相对路径、文件大小和 SHA-256。Markdown 供人工核对。只有发布日期属于目标日的文章才进入归档。没有正文的文章保留元数据。

采集先在同一文件系统的临时目录完成。全量重跑成功后原子替换当天目录，单来源重跑成功后更新对应来源。失败或中断时保留已有正文和图片，并在 `report.json` 的 `latest_attempt` 记录结果。首次采集失败但仍有可用结果时，归档保留已成功保存的文章及失败状态。强制终止且来不及生成报告时，以任务状态和服务日志为准。

## B 的读取和入库

| 接口 | 返回 |
|---|---|
| `GET /transfer/v1/days/{date}` | 目标日的可同步文章、来源状态和文件校验信息 |
| `GET /transfer/v1/days/{date}/files/{path}` | 报告中指定的正文或图片 |

两个接口均使用同步 Bearer 令牌。日期尚无归档时返回 404。B 验证文件大小、SHA-256、文章发布日期及图片类型，再写入 MySQL 和对象存储。按来源提交事务，相同文章 ID 更新现有记录。同一个来源的结果重复同步时复用本地检查点。B 在 `data/incoming/days/YYYYMMDD.json` 保存已同步的日期结果。

A 和 B 的生产代码应配套更新，并保留 B 的 `state/sync.sqlite`。旧日期目录中的正文和图片可直接通过日期接口读取。
